# 什么是Hash

哈希(Hashing) 就是把一个输入空间中的数据，通过某种确定的规则，映射到另一个通常更小、有限的输出空间

写成数学的形式就是

\[H(x) = y\]

- \(x\)：输入
- \(H\)：哈希函数
- \(y\)：哈希值

```
任意长度的数据
v
Hash Funtion
v
固定范围的整数 / 固定长度的数据
```

## 哈希的本质：映射

假设有一堆字符串

```
Alice
Bob
Charlie
Davie
```

我们希望把它们放进一个大小为`8`的数组，但字符串本身不能直接作为数组下标，因为数组需要的是整数

```cpp
// array["Alice"]; // Error
array[0];
array[1];
```

所以

```
"Alice"   --Hash--> 3
"Bob"     --Hash--> 6
"Charlie" --Hash--> 1
"David"   --Hash--> 5
```

于是

```
Array
┌─────────────┐
│ 0           │
├─────────────┤
│ 1  Charlie  │
├─────────────┤
│ 2           │
├─────────────┤
│ 3  Alice    │
├─────────────┤
│ 4           │
├─────────────┤
│ 5  David    │
├─────────────┤
│ 6  Bob      │
├─────────────┤
│ 7           │
└─────────────┘
```

这就是哈希最经典的一种用途：把原本不方便直接处理的数据，映射成方便计算和定位的值

## 为什么需要哈希

现实中的数据空间通常非常大，比如字符串可以无限长，但是我们只希望得到一个64-bit整数，那么输出空间就只有\(2^64\)种结果，这就是一个压缩映射，不论输入多大，输出都可以保持固定长度

## 哈希碰撞

假设一个哈希函数

```cpp
hash(x) = x % 10;
```

则

```
1 -> 1
11 -> 1
21 -> 1
31 -> 1
41 -> 1
...
```

不同的输入经过哈希函数后得到了相同的输出，这就叫Hash Collision（哈希碰撞）

根据鸽巢原理：只要鸽子数量大于鸽巢数量，就一定有至少两个鸽子进入同一个巢穴\
输入空间是无限的，哈希函数确定且唯一的情况下，输出空间是有限的\
所以，对于任意将大空间压缩到小空间的Hash，碰撞是数学上必然存在的

一个好的Hash不是没有碰撞，而是碰撞难以发生，分布良好，符合应用需求

## 哈希函数

哈希函数的作用是不断对输入数据进行Mixing（混合），让输入的信息充分扩散到输出中

比如一个字符串`hello`，内存中本质上是字节

```
h    e    l    l    o

68   65   6C   6C   6F
```

一个Hash Function 可能不断执行

```
读取数据
   ↓
XOR
   ↓
Multiply
   ↓
Rotate
   ↓
XOR
   ↓
Multiply
   ↓
Rotate
   ↓
...
   ↓
Finalization
```

伪代码可能像

```cpp
uint64_t hash(const char* data, size_t size) {
    uint64_t h = SEED;

    for (size_t i = 0; i < size; i++) {
        h ^= data[i];
        h *= PRIME;
        h = rotate_left(h, 13);
    }

    return h;
}
```

这里最重要的是

```
输入
v
不断 Mixing
v
输入的每个部分逐渐影响更多 Bit
v
最终得到 Hash Value
```

例如 `00000001`，经过好的Mixing 会生成Hash `101101101001010011101...`\
就算只改动一个Bit变成`00000000`，理想情况下，输出会变成`010010110110101001011...`\
这种性质就叫Avalanche Effect（雪崩效应）

## Hash的分类

不同Hash追求的目标不同

两大主流应用场景

1. 数据结构（哈希表）：追求高效查找与映射。利用哈希函数将key计算为数组下标，从而实现接近\(O(1)\)时间复杂度的元素插入与检索
    - 期望：快-> Hash计算成本低，均匀-> Key 尽量分散到不同位置，碰撞少 -> 减少冲突处理
    - 常见算法：MurmurHash, xxHash, CityHash等（注重计算速度，不防恶意攻击）
    - 典型用途：标准库中的`unordered_map` / `std::unordered_map`, Redis字典、数据库索引
2. 密码学与安全（密码学哈希）：追求抗碰撞性与单向不可逆，用于数据完整性校验和身份验证，攻击者可能会故意寻找漏洞
    - 期望：确定性，雪崩效应，抗碰撞，抗原像攻击，抗第二原像攻击
    - 常见算法：SHA-256, SHA-3, BLAKE3（MD5和SHA-1因已被攻破，现仅用于非安全场合）
    - 典型用途：
      - 密码存储：数据库不存明文密码，仅保存密码的哈希值（通常配合加盐Salt）
      - 完整性校验：Git提交的Commit Hash，文件下载后的校验和(Checksum)
      - 区块链与数字签名：构建Merkie树与工作量证明(PoW)

Hash可以用于加密，但Hash不等于加密

# 硬件层

硬件物理层面哈希的核心议题是：如何让CPU架构、内存体系和硬件指令集，以极致的物理效率去执行哈希算法与数据存取

上层不论算法多么优雅，最终都要转化为CPU指令、高频读写L1/L2/L3缓存和操作物理内存\
硬件层对哈希的影响主要体现在以下四个物理维度：

## 硬件级哈希指令(CPU Hash Hardware Acceleration)

为了极速完成哈希计算，现代CPU(x86, ARM)在芯片设计时，直接将某些哈希算法的计算逻辑写进了硬件晶体管里，提供了专属的CPU指令

- CRC32 指令：Intel的SSE 4.2指令集直接内置了`CRC32`指令，单个指令周期就能完成一个字节的CRC校验计算。像MongoDB，部分数据库系统底层就会直接调用CPU的`CRC32`指令来充当快速哈希函数
- AES-NI 指令集：硬件加速的AES加密指令。现代高性能哈希（如meowhash)利用CPU内置的AES加密电路进行比特位打散，计算速度可以达到惊人的50GB/s（几乎等同于内存读取带宽）
- SHA加密扩展：x86和ARM芯片都包含专门加速SHA-1/SHA-256计算的硬件指令（如`SHA256RNDS2`），让加密哈希在硬件层面并发运行

## 缓存行与内存局部性(Cache Line & Locality)

这是对上层哈希容器设计影响最大的物理因素

- 物理实现：CPU读写内存不是一个字节一个字节读的，而是以64字节(Cache Line)为单位，一口气将连续的物理内存加载进L1/L2缓存。CPU访问L1缓存只需要~1 ns，而直接访问主存(RAM)需要~100ns
- 物理层的惩罚：
  - 链地址法(Java HashMap)：链表节点的内存是散落分布的。沿着指针跳下一个节点，极大概率触发 Cache Miss，CPU必须强制停下来等待内存读取
  - 开放寻址法(Python dict / Rust SwissTable)：把槽位连续紧凑地摆在内存数组里。CPU一次抓取64字节，能顺便把相邻的几个哈希槽位一次性全部载入Cache，后续的碰撞探测几乎100%命中缓存，速度天差地别

## 单指令多数据流并行计算(SIMD 指令集)

现代CPU（如Intel AVX2/AVX-512，ARM NEON）拥有SIMD(Single Instruction, Multiple Data)矢量寄存器，允许CPU在一个时钟周期内对多个数据并行执行相同操作

这直接改变了现代高阶哈希容器（如Google SwissTable, Rust HashMap）的底层设计：

- 做法：它们将哈希值的高57位用于定位，低7位（控制位）打包提取出来
- 硬件加速：使用AVX2的`_mm256_cmpeq_epi8`指令，CPU可以在一个指令周期内同时对比16个或32个槽位的Control Bit
- 效果：以往需要循环对比16次的冲突探测，在硬件层面被一次完成

## 内存对齐与位运算(Memory Alignment & Bitwise Ops)

在电路设计层面，CPU访问对齐的内存地址（如64位系统上按照8字节边界对齐的地址）速度最快，而非对齐访问会导致CPU发起两次内存总线请求甚至抛出硬件异常

- 对齐与掩码：在将哈希值映射为数组下标时，传统数学算术是`hash % capacity`（除法运算在CPU上极其昂贵，需要几十个时钟周期）
- 硬件优化：如果上层强制要求数组容量`capacity`必须是\(2^n\)，底层就可以按位与运算(`hash & (capacity - 1)`) 替代除法取模。在CPU硬件电路中，按位与运算只需要1个时钟周期，效率提升数十倍
