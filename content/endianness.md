字节序，又称端序，是指多字节数据在内存中的字节排列顺序

在计算机中，基本的存储单位是字节(1Byte=8bit)，每个字节都有一个唯一的内存地址。当存储占多个字节的数据类型（如16位的`short`, 32位的`int`或64位的指针）时，计算机必须决定如何将这些字节按顺序排放到内存地址中

## 两种核心字节序

假设有一个32位的十六进制整数：`0x12345678`\
它由4个字节组成（从高位到低位）：`12`（高位字节）, `34`, `56`, `78`（低位字节）\
其中，数据高位字节`12`（权重最高，代表数值的大头），数据低位字节`78`（权重最低，代表数值的尾巴）

- 小端序(Little-Endian)：低位字节存放在低地址，高位字节存放在高地址
  - 特点：符合计算机的加法计算逻辑（CPU从低位开始做加法进位）
  - 常用环境：x86/x86-64 Architecture, ARM
- 大端序(Big-Endian)：高位字节存放在低地址，低位字节存放在高地址
  - 特点：符合人类对数字的阅读习惯（从左到右）
  - 常用环境：网络传输协议（IP/TCP 规范统称为“网络字节序”），部分RISC架构（如早期PowerPC, SPARC）、部分大型机（如IBM z/Architecture）

### 内存布局对比

在低地址为`0x1000`的内存位置写入`0x12345678`时

| 内存地址 | Big-Endian | Little-Endian |
| - | - | - |
| `0x1000`(低地址) | `0x12`（高位）| `0x78`（低位）|
| `0x1001` | `0x34` | `0x56` |
| `0x1002` | `0x56` | `0x34` |
| `0x1003`（高地址）| `0x78`（低位）| `0x12`（高位）|

## 字节序的重要性

字节序在单字节操作（如ASCII字符串，`uint8_t`数组）上是没有区别的，但在跨平台和底层开发中必须关注

1. 网络通信：网络协议统一采用大端序(Network Byte Order)。若小端架构主机发送数据，必须先转换为大端序发送；接收方再将网络字节序转回主机字节序(Host Byte Order)。(POSIX 提供了 `htons()`, `htonl()`, `ntohs()`, `ntohl()`系列转换接口)
2. 二进制文件解析：图像(PNG, BMP)，二进制模型文件或可执行文件在设计格式时会显式指定字节序。解析器需要做出相应的类型安全转换
3. 底层指针与联合体强转：在C/C++中对内存进行按字节切片或强转时，不同字节序结果完全一致或不一致

为什么Little-Endian成为桌面设备主流

x86/x64架构(Intel, AMD) 以及大多数ARM芯片（如手机）默认采用小端

CPU加法器是从最低位（个位）开始做加法和进位的。如果低位字节刚好存在内存低地址，CPU顺着内存地址由低到高读取数据时，可以一边读一边直接参与运算，电路逻辑设计最简单，硬件计算效率高

将`int`（4Byte）强制转换为short(2Byte)时，在小端机器上直接截取低地址的2字节即可，不需要重新计算指针偏移量

Big-Endian出现在网络传输中，TCP/IP协议族明确规定，网络传输数据必须统一使用大端模式。因为大端符合从前往后的阅读顺序，方便路由设备在数据流刚刚到达时快速读取头部字段（如IP地址、数据包长度）

## 判断当前系统字节序

```c
#include <stdio.h>
#include <stdint.h>

// 方法1：强转保留低位看结果
int func1() {
    uint32_t val = 0x01;
    uint8_t *byte_ptr = (uint8_t *)&val;

    if (*byte_ptr == 0x01) printf("Little-Endian\n");
    else printf("Big-Endian\n");

    return 0;
}

// 方法2：使用union中所有成员共享同一块起始内存的特性，文明转换类型
int func2() {
    union {
        int i;
        char c;
    } test;

    test.i = 1;
    
    if (test.c == 1) printf("Little-Endian\n");
    else printf("Big-Endian\n");

    return 0;
}
```

需要考虑端序的场景，是“把数据当作字节序列交给另一个东西”\
平常在一个设备内，编译器和操作系统帮你隐藏了很多细节，你不需要关心一个数据在内存中是高位在低地址，还是低位在低地址，CPU指令集自己知道怎么解释
